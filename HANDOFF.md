## Decisions made
- **Stack**: React+Vite PWA · Cloudflare Workers (free) · Supabase Postgres+auth+storage (free).
- **Places pricing**: `rating` + `userRatingCount` are **Enterprise** fields (Place Details Enterprise), **1,000 free/month**; internal cap **900**. If daily snapshots would exceed it, snapshot less often (frequency = ceil(active×30/900)).
- **Review tracking is optional**: a missing or blank `GOOGLE_PLACES_API_KEY` disables Places entirely — `GET /status` reports `places_connected:false`, the snapshot cron logs a skip and returns (no failed job). The dashboard and admin still show texts/clicks/click-rate and whatever manual counts an admin has entered, with "Mur Systems adds the count until Google tracking is connected."
- **Results**: "this month" is the Melbourne calendar month (same boundary as the allowance); click rate is clicks on texts sent in that period ÷ texts sent in it. `messages.mock` is excluded everywhere, so test and mock sends never count. Manual Google counts are ordinary `review_snapshots` with `source='manual'`, so they power the numbers and the chart until Places is on. The starting count recorded when a business is created (or the earliest snapshot if none was recorded) is the baseline for "reviews gained since joining".
- **Send modes**: `sms_provider` (default, Mobile Message) · `android_gateway` (SMSGate, optional) · `demo` · `log_only`. Live switch = `SENDER_LIVE` (off). `PRODUCTION` unset. `SEND_ALLOWLIST` = operator's number only.
- **SMSGate**: cloud relay recommended; E2E (RSA+AES-GCM) **not** implemented (deferred). **Mobile Message**: sender = "own mobile number", verified in dashboard (4-digit code), no documented limit; ACMA Register is for business-name senders only.
- **Defaults**: delay 60 min · quiet hours 9am–8pm (Melbourne) · reminder at 3 days · `daily_send_cap` (import drip) **15** · `daily_text_cap` **100** · `monthly_text_cap` **500** · `trial_text_cap` **30** · demo send 1/30d per number + 20/day · tokens 8-char base62.
- **Brand**: product **"Mur Reviews"**, company **"Mur Systems"** ("by Mur Systems" on the login page only). Colours: black `#0c0c0c`, gold `#c8a45c`, ivory `#f4efe6`, ink `#14110d`. Cinzel (Google Fonts) for the logo, product/business names and headings only; everything else sans-serif. The theme follows the device until the user picks light or dark (login corner, app header, or Settings → Appearance); the choice is saved per device. On ivory, text and buttons are ink and gold is only thin lines/small accents; dark is the original black/gold. All in `frontend/src/config.ts` and `frontend/src/theme.ts`.
- **Logo**: code-only component `frontend/src/components/Logo.tsx` — Cinzel "M" in a thin outer ring + slightly heavier inner ring, with a "MUR REVIEWS" wordmark; `compact` prop gives the ring-only mark used in the owner header.
- **What's new**: `config.whatsNew.version` + `message`; shown once per user, dismissed in localStorage under `mur-whats-new:<userId>`.
- **App icon/PWA**: gold M ring on black, PNGs 32/180/192/512 in `frontend/public/`; manifest name "Mur Reviews". The old purple `favicon.svg` was removed.
- **Monthly allowance**: 500 texts per plan month by default (`businesses.monthly_text_cap`), resetting at 00:00 on the 1st in `Australia/Melbourne`. First texts and reminders count; `messages.mock=true` never does. Usage/state comes from `business_text_usage` (service-role) and `owner_text_usage` (owner/admin, RLS-checked); states are `ok`, `warning` (≥80%) and `paused` (≥100%). At the allowance `claim_due_messages` claims nothing, so queued rows wait; `expire_stale_queued_messages` fails queued rows more than 7 days past `scheduled_at` with `retryable=false`. Admins raise one business's allowance via `admin_set_monthly_cap` (audit action `set_monthly_cap`).
- **Templates**: shortened; end with `Opt out: {opt_out}`; one segment (two only for long names). Mock sends carry `messages.mock=true` and are excluded from all stats.
- **Activity**: owner screen reads the latest 20 `messages` and 20 `replies` directly (RLS-scoped) — no placeholder left. Status is derived from `clicked_at` first (legacy rows recorded a click without changing `status`), then `messages.status`: `sent`/`clicked` → "Sent"/"Link opened", `cancelled` → "Cancelled", `opted_out` → "Opted out". A failed text also shows `last_error`, which holds a plain owner-safe reason. For `android_gateway` businesses the Replies section is replaced by "Replies come straight to your phone, since texts are sent from your own number."; opt-outs still use `/o/{token}`.
- **Inbound replies**: Mobile Message inbound webhook at `POST /webhook/mobile-message`, subscribed account-wide (`inbound` type) via `POST https://api.mobilemessage.com.au/v1/webhooks`. Auth is the signing secret when `MOBILE_MESSAGE_WEBHOOK_SECRET` is set (`X-MM-Timestamp`/`X-MM-Signature`, HMAC-SHA256 of `{ts}.{rawBody}`, ±5 min), otherwise the `?key=` secret compared against `MOBILE_MESSAGE_INBOUND_KEY`; neither → 503. Sending passes `custom_ref` = message id. Matching order: exact `custom_ref` → most recent text to the number in 90 days (preferring the business whose `sender_number` is the number replied to) → business by `sender_number`. Replies store `customer_id`, `message_id` and `kind` (`reply`/`stop`), and are deduped on `(business_id, from_mobile, received_at)` because webhook retries replay the same payload. `type=unsubscribe` and STOP-like text opt the number out (`source='reply'`) and cancel queued/sending messages.
- **Cancelled vs failed**: `message_status` has `cancelled`; stale queued texts (7 days) and `cancel_dev_messages` use it. `failed` means a real provider/DB failure and carries a plain `last_error` written by `ownerFailureReason()`; the more technical `sendFailureReason()` is only the admin test-response/log text.
- **AI reply interest**: `public.ai_reply_interest` (PK `business_id`, `requested_by`, `created_at`); owners may select/insert their own row, update/delete revoked, so one request per business. `admin_list_businesses()` now returns `ai_replies_requested_at`, which the admin table renders as a gold pill.
- **Admin theme**: admin uses the same theme as the owner app (light by default, dark when selected); it no longer forces the dark token set.
- **Auth**: email+password (primary) + magic link (secondary); owners onboarded via `invite` (set-password) link, reset via `recovery` landing on `/set-password`. The login page never checks or reveals admin status — no email list in the bundle, no pre-login lookup, and the same UI for every address. The magic-link option is hidden for everyone until client email delivery exists (`config.auth.signInLinkForEveryone: false`); once true it is shown uniformly. Admin status comes only from `profiles.role = 'admin'`, read after login from the authenticated session; the Worker's `/admin/*` guard verifies the caller's JWT and role on every request. Any logged-in user can set/change their password in Settings. "Forgot password?" tells users to contact Mur Systems until reset email exists; until then an operator can mint a recovery link with the admin `generate_link` API. Recovery and expired-link errors are surfaced through `frontend/src/authLink.ts` and the copy in `frontend/src/errors.ts` — never show a raw Supabase/Postgres/Worker message.
- **Legal pages**: `/terms` and `/privacy` render without a session (public paths, SPA fallback already configured) and are linked from the login footer and Settings → Legal. Both are marked **draft for legal review**; Mur Systems is named with ABN 22 545 735 809. They state Supabase storage in Sydney (`ap-southeast-2`), retention periods, client responsibility for real customers/consent, opt-outs and deletion via the Mur Systems account contact.
- **Logo URL**: storage RLS already confined uploads to `logos/<business id>/`; migration `20261117241000` adds a `businesses` trigger so a non-null `logo_url` must match `https://<host>/storage/v1/object/public/logos/<business id>/<file>` (query string allowed). pgTAP covers own/foreign/external URLs.
